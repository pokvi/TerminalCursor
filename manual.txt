  АВТО-ЗАПУСК ИГРЫ — РЕШЕНО (что было и почему не здесь)

Раньше в этом репо был AutoStart.cs, который пытался "нажимать клавиши"
(down/enter/esc) для прохода меню и создания лобби. Это ТУПИКОВЫЙ путь:
  - Unity New Input System не видит keybd_event/SendInput со скан-кодами;
  - нужен фокус окна; хрупко.
Рабочее решение - отдельный плагин (репо LethalCompany_AutoStart), который
ходит через ПРЯМЫЕ вызовы игрового API, без клавиш:
  - экран LAUNCH MODE: PreInitSceneScript.ChooseLaunchOption(online:false)
    => грузится сцена "InitSceneLANMode" (там disableSteam=true, это и есть LAN);
  - меню: GameNetworkManager.StartHost();
  - терминал: Terminal.GetComponent<InteractTrigger>().Interact(player.transform)
    - это ШТАТНЫЙ вход игрока. При specialCharacterAnimation=true он зовёт
      BeginUsingTerminal() и подводит+доворачивает игрока к монитору.
      Прямой BeginUsingTerminal() поднимает terminalInUse, но экран терминала
      НЕ видно: это World Space Canvas на мониторе корабля, а игрок стоит
      в стороне и на него не смотрит.
Проверено: игра доходит до открытого И ВИДИМОГО терминала без человека.

Реализовано в Plugin.cs (коммит 4e27db0 + правки после него):
  - Подсветка ВСЕХ команд постоянно (голубой), ховер - жёлтый; канонические
    вхождения (заголовки '>MOONS', '"Help"') ярче, прочие - приглушённо.
  - Клик = штатный путь: дописать слово в screenText.text (+ страховка

    help/bestiary/moons/store/assurance/confirm/walkietalkie все ведут
    в правильные узлы.
  - Хит-тест: TMP_TextUtilities.FindIntersectingCharacter + конверсия мыши
    в пространство камеры ToCamSpace (игра рендерит 970x580 при экране
    2560x1440 - без конверсии все хиты промахиваются).
  - Фильтр кликабельных слов (UpdateClickableCache): nouns с defaultVerb,
    слова с specialKeywordResult (help/scan), accessTerminalObjects,
    overrideOptions (confirm/deny). Одиночные глаголы (route/buy) НЕ
    кликабельны - игра на них даёт ParserError.
  - НЕ звать ForceMeshUpdate из мода: рассинхрон с TMP_InputField
    (уезжают каретка и label). Пересборка кэша подсветки по сигнатуре
    (text + characterCount + maxVisibleLines).
  - Собственный runner-объект (DontDestroyOnLoad + HideAndDontSave):
    GameObject плагина игра уничтожает при первой загрузке сцены, Update
    плагина не вызывается. Создавать через EnsureRunner().

  - ПОДСВЕТКА МНОГОСЛОВНЫХ НАЗВАНИЙ (store-товары). Терминал выводит
    display-имена, которые часто не совпадают с ключами парсера.
    Игра в ParsePlayerSentence сначала снимает пунктуацию (RemovePunctuation),
    затем проверяет CheckForExactSentences(s) — s == kw.word ДОСЛОВНО.
    Сырые ключи игры: "zap gun", "inverse teleporter", "extension ladder",
    "loud horn", "weed killer", "belt bag", "spray paint", "pro flashlight",
    "green suit" — все СОДЕРЖАТ ПРОБЕЛЫ. И "walkie-talkie" — С ДЕФИСОМ.
    Normalize() уничтожал пробелы и дефисы, поэтому ExecuteCommand слал
    "inverseteleporter" — CheckForExactSentences не находит точного совпадения,
    скатывается к ParseWord → находит "teleporter" → покупает обычный
    телепортер за 375 вместо инверсного за 425.

    Display-имена товаров НЕ совпадают с ключами:
      "Stun grenade"  → ключ "stun" (одно слово)
      "Signal Translator" → ключ "signal" (одно слово)
      "Sofa chair"   → ключ "sofa" (одно слово)
    Поэтому нужен отдельный проход матчинга display-имён.

    BuildCommandRanges теперь в 3 прохода (каждый диапазон хранит сырой ключ):
      0. Display-имена из текста: ParseDisplayNames извлекает строки вида
         "* Название  //  Price: ¤X" (или "//  Цена:"). Разделитель "//"
         locale-independent — работает и с RTLC (русский перевод).
         Для каждого display-имени ищем ключ: точное совпадение в keyMap,
         иначе самый длинный ключ-префикс ("stungrenade" → "stun").
         Подсвечиваем ВЕСЬ товар целиком: "Stun grenade", "Signal Translator".
      1. N-граммы 1-3 слова: "Zap gun" → keyMap["zapgun"]="zap gun".
         "Inverse Teleporter" → keyMap["inverseteleporter"]="inverse teleporter".
         Дедуп в AddRange: "Inverse Teleporter" добавляется раньше "Teleporter"
         (w идёт по возрастанию), поэтому дедуп отбрасывает короткое.
      2. Дефисные токены: "TZP-Inhalant" → сегмент "tzp" → ключ "tzp",
         но подсвечиваем ВЕСЬ токен (пользователь кликает по любой букве).
    Проверено в логах игры:
      click 'inverse teleporter' → noun keyword: inverse teleporter → InverseTeleporterBuy
      click 'teleporter'       → noun keyword: teleporter           → TeleporterBuy1
      click 'signal'           → noun keyword: signal               → SignalTranslatorBuy
      click 'pajama suit'      → noun keyword: pajama suit         → PajamaSuitBuy1
      click 'tzp'              → noun keyword: tzp                 → buyTZP
    Для совместимости с RTLC: названия товаров на экране остаются на
    английском (переведены только "Цена:", заголовки). Если мод переведёт
    названия товаров — ключи не совпадут, но это редкий кейс.


РЕШЕНО (коммит 843f1c1):
  Мигание каретки input-поля в случайном месте текста — ИСПРАВЛЕНО.
  Причина: Terminal.Update каждый кадр делает screenText.caretPosition =
  text.Length. caretPosition — это ИНДЕКС В textInfo, а не строковый индекс.
  При смене узла текст уже новый (len=268), но textInfo.characterCount ещё
  старый (cc=157). Сеттер caretPosition клампит 268 до 156, поднимает
  m_IsStringPositionDirty. В OnFillVBO из caret-индекса 156 пересчитывается
  строковая позиция 156 — наша позиция конца затирается. Один кадр каретка
  рисуется по textInfo[156] новой раскладки = середина текста.
  Проверено Harmony-логами (cc, cp, sp каждый кадр):
    ДО:  fill cc=157 sp=268 cp=156 -> fill cc=269 sp=156 cp=156 (середина)
    ПОСЛЕ: fill cc=157 sp=268 cp=156 -> fill cc=269 sp=268 cp=268 (в конце)
